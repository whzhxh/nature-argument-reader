# 深入批注：让侧栏提供正文之外的认识

## 用法与目标

在通读来源、建立主张与证据索引后使用。本指南提供分析视角，不要求每段填满。
目标是解释“为什么成立、如何成立、成立到哪里”，不是把译文换一种说法。
重要机制、方法、结果和讨论段通常值得深入；导航句、出版信息、参考文献
不必生成与科学论证无关的长评。一个小而具体的推导优于数个泛泛标签。

**深度不等于默认篇幅。** 每段默认只展开最有价值的一条判断，正文通常一至三句。
依据、推导影响和核验办法按需展开；额外视角收进“更多分析”。
作者原文短引可折叠，但依据锚点保留可见。不以全展开的长侧栏反复拉开正文，
也不为了达到字数目标强行增加分析。选择能改变读者理解的内容，省去术语堆砌。

## 先做全局索引，再写局部批注

对核心主张记录：准确范围 → 机制或必要假设 → 实际证据及位置 →
最强支持 → 未闭合环节 → 会改变判断的检验。
区分设计意图、实现描述、实验观察、作者解释和模型推导。
把结果段连接回方法和引言，避免在引言批评“没有证据”却不检查后文。

段落功能和逻辑角色是导航信息，不能单独充当深入分析。
用 `analysis.insights` 呈现实质内容；旧四槽位保留，渲染器会将它们收进
“段落作用与论证衔接”，不与深入分析争抢首屏。

## 写出连续的推理，而非段落标签

承担科学论证的段落可增加 `analysis.connections`。展开后按四步阅读：

1. **承接前文**：具体继承哪条主张、未解决问题、定义或约束？为什么需要本段？
2. **本段推进**：本段改变了读者对什么的认识：界定对象、提出机制、
   操作化变量、建立对照、报告观察，还是缩小结论范围？
3. **推理桥梁与证明责任**：从本段材料到目标主张需要什么条件？
   区分设计意图与实测成立、相关与因果、局部机制与端到端保证。
   说明实验/推导需要排除什么解释，以及哪里已经履行这项责任。
4. **引向后文**：定位后文如何检验、依赖或限制本段；
   结论段则回扣已验证的范围并闭合论证，不伪造后续验证。

使用真实相关块的来源链接，关系须有具体内容，不写“为后文奠定基础”
就结束。方法段可以指向实验，结果段可以回到方法和引言，不按版面邻接代替依赖。
开篇没有前提段、出版信息无科学衔接时保留普通功能分析，不强填四步。
这些关系全部属于模型解读，不能因带了来源链接就标作作者明示。
链条默认折叠，同一科学问题不在各步骤重复大段评述。

## 术语释义提供进入分析的入口

将侧栏中理解机制所必需的关键词与缩写放入有来源的 `glossary`。
释义通常一句，本文语境一句；只在易混淆时补边界，例如：
“错误检测”与“错误纠正”、“单次注入比例”与“部署失效率”不能互换。
为释义绑定相应段落，直接论文定义用 Paper；模型归纳和通俗解释用 Analysis。
词典不是额外知识百科，不把未由材料支持的通用机制或外部结论写成论文事实。
含义不同的缩写不得共用一个条目；别名用于真正同义的中英名称。
解释窗口按需出现，不增加默认侧栏篇幅，也不改动原文与译文。

## 选择与证据相符的视角

| lens | 应回答的具体问题 | 有价值的输出 |
|---|---|---|
| mechanism | 输入、状态、操作、输出和失败路径如何连接？ | 分解状态更新顺序、不可逆操作、比较/恢复的前提；指出关键设计为何必要 |
| evidence | 这幅图或这次实验究竟支撑哪条主张？ | 区分相容性与排他性证据、设计目标与实测结果，说明支持到哪一层 |
| assumption | 推理依赖哪个条件，条件失败后会怎样？ | 明确条件 → 推导变化 → 影响；不要空写“存在假设” |
| comparison | 比较双方是否在解决相同任务、付出相同预算？ | 核对基线、保护范围、负载、工艺、频率、恢复能力与计量分母 |
| quantitative | 数字对应什么对象、单位、分母、区间？ | 给出可复算的计算，区分百分点/相对百分比、功率/能量、条件概率/任务可靠性 |
| alternative | 同样观察还可能由什么机制产生？ | 说明尚未排除的解释以及可区分两种解释的对照，不宣称替代解释已被证实 |
| boundary | 哪些对象、场景或故障类型尚不能外推？ | 精确指出从已测系统到目标系统改变的条件，以及迁移需要补什么证据 |
| reproducibility | 哪些参数足以改变结论，如何重现？ | 指出版本、样本单位、种子、配置、工作负载、超时、判据与需要的材料 |
| connection | 跨段或图表之间有哪些隐含依赖？ | 把问题、机制、实验和结论连接起来，说明一处限定如何改变另一处解释 |

写作单元为：

1. **具体标题与判断**：给出读者能带走的新认识。
2. **依据与推导**：引用真实段落/图表，解释为何能得出判断。
3. **对结论的影响**：关系到机制解释、主张强度、工程选型或复现的哪一点？
4. **如何核验（适用时）**：可区分解释的实验、计算、波形检查或应核查的材料。
   若已有充分支持，不必凭空要求追加实验。

不得把这套字段变成一律“作者没做”的批评模板。优点也要说明为什么证据有力。
同一洞见在主要证据段展开，其他段只补新的推理或用依据链接连接，避免重复堆字。

## 与论文类型匹配

- **方法/系统**：分清核心原理与实现配套；消融是否只改变待验证因素；
  基线是否同预算、同任务；端到端成本是否包含预处理和配套模块。
- **实验发现/机制**：观察是否能区分竞争解释；干预和对照是否支持因果；
  不把相关性、预测精度或代理指标视为机制证明。
- **理论**：逐项核对假设、量词、证明依赖和边界案例；不能将有限实验当作证明。
- **临床/统计**：先明确分析单位、结局、独立重复、效应量和不确定性；
  有适用依据才使用专门框架。不得将 GRADE、临床风险偏倚工具套到处理器实验，
  也不把检查项数量换算成论文质量分数。
- **综述/资源**：核对检索/收录范围、来源质量、覆盖偏差、资源复用与外部验证；
  综述所转述的结果不是该综述新获得的实验结果。

## 处理器与可靠性论文的具体检查

这些检查仅在论文主张触发时使用，不要求所有论文逐项通过。

- **故障模型与物理对象**：区分配置位、架构状态、微架构触发器、组合网络；
  单次位翻转、短脉冲、永久故障、多位/多点相关故障的结论不可互换。
- **提交与恢复**：第一次执行是否改变状态？外部事务是否已不可撤销？
  正确结果、检测、掩蔽、纠正、恢复和超时各是什么判据？保护逻辑自身是否在故障集合内？
- **时间与空间多样性**：错时双核和单流水线重执行不是同一个机制；
  持续故障可能同时影响两次执行。说明条件，不将可能性写成发生事实。
- **公平比较**：同核/同工艺是优势，但还须核对 ISA 配置、存储协议、保护范围、
  时钟、负载、恢复逻辑和面积分母。增量包装成本与完整系统成本分别解释。
- **PPA 口径**：额外开销 +86% 对应总量 ×1.86；等频率和等吞吐量要区分；
  平均功率较小不自动意味着单任务能量较小，E = P × T 需在一致测量条件下使用。
- **注入统计**：明确抽样总体、采样分布、独立单位、每轮恢复、超时和正确性判据。
  大样本只缩小指定抽样模型下的误差，不保证工作负载、真实辐射或部署场景代表性。
- **可靠性指标**：所有注入中的成功比例、有效故障中的纠正比例、
  残余错误降低比例以及物理环境失效率是不同量，核对分子分母。
  零次观测失败也不是零风险证明。模型计算置信界限时注明抽样假设与计算来源。
- **选型与泛化**：选择性加固与工作负载、配置和布局相关；核对模型选择与验证
  是否复用同一组负载。FPGA LUT/FF/BRAM 不合并成无单位“面积”；
  ASIC、FPGA、不同工艺与不同保护范围不能直接排成确定名次。

## 语义验收

逐条问：读者是否从这里获得译文没有直接提供的解释？依据是否真的支持推导？
是否误读了指标或量词？全文其他地方是否已回答这个疑问？提出的检验是否会改变
当前判断，而且成本与主张相称？一条都不能回答的内容删掉，不靠字数补深度。

不把“材料未报告”写成“实验未做”，不制造数值置信分，不强凑优缺点数量；
缺少原始数据时只核读已报告数字，不伪装成重新分析或独立复现。

## 方法来源与采用边界

本指南以原创表述整合分析方法，不复制、安装或执行外部技能。
截至 2026-11-11 核读：

- 本地 `nature-paper-card` 的 methods 片段：主张—证据矩阵、组件消融、匹配预算。
- 本地 `nature-reviewer` 的 technical-concern-taxonomy 与 engineering gates：
  观察—证据—对主张的影响—解决检验；以影响校准问题，不强制问题配额。
- 本地 `nature-statistics`：分析单位、分母、重复与不确定性。
- K-Dense `scientific-critical-thinking`：
  https://github.com/K-Dense-AI/scientific-agent-skills/tree/main/skills/scientific-critical-thinking
  借鉴有效性分类与主张、证据、假设的分离；未引入临床证据等级或第三方服务。
- ByteDance DeerFlow `academic-paper-review`：
  https://github.com/bytedance/deer-flow/tree/main/skills/public/academic-paper-review
  借鉴具体观察、位置、影响及建设性建议；未采用固定打分、问题配额与录用判断。
- JunMA98 `scientific-critical-thinking`：
  https://github.com/JunMA98/Computer-science-claude-skills/tree/main/skills/scientific-critical-thinking
  借鉴系统负载、比较预算、代理指标与可证伪性检查。

这些是分析方法的参考，不是对当前论文技术结论的外部证据。
本阅读器保持 Paper / Analysis 分区和单文件交付，不自动变成完整审稿或外部检索。
